# Git-панель в боковой колонке — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** блок с иконкой git и счётчиком изменённых файлов между spaces и files; по клику — своё дерево изменений; по файлу — сравнение «HEAD | сейчас» в две колонки.

**Architecture:** новый модуль `ui/git_changes.py` (чистые функции: список изменений, строки сравнения) → два метода `Api` в `ui/bridge.py` → JS/CSS чата: блок `#git-box`, вкладка редактора вида `diff`.

**Tech Stack:** Python 3 (subprocess git, difflib), pywebview, ванильный JS/CSS чата.

**Spec:** `docs/superpowers/specs/2026-10-26-git-panel-design.md`

## Global Constraints

- Никаких `__init__.py`; импорт из конкретных модулей (`from ui.git_changes import ...`).
- Ничего не коммитить (правило пользователя) — шаги «Commit» в этом плане отсутствуют.
- Стиль кода как вокруг: блочные комментарии `# ---- / # что делает / # ----` (в JS `// ----`), русские тексты в UI в нижнем регистре, как у соседей.
- Цвета только из токенов `ui/theme.css` (`--accent`, `--diff-add`, `--diff-del`, `--muted`, …) — работают в светлой и тёмной теме.
- pytest в venv нет и ставить его не надо: проверки — скрипты в scratchpad на временном git-репозитории.
- Дерево `#files` не меняется никак.

## Review Focus

1. Пространство — подпапка репозитория (не корень): пути и счётчик только по файлам внутри пространства, пути от корня пространства.
2. Папка не под git / git не установлен / репозиторий без коммитов: иконка серая без ошибок; в пустом репо всё — `U`, левая колонка пустая.
3. Имена с пробелами и кириллицей: porcelain `-z`, без кавычек и `\nnn`-экранирования.
4. Двоичный или огромный файл: вместо сравнения — строка «двоичный файл» / обрезка, интерфейс не зависает.
5. Ctrl+S / Ctrl+W на вкладке сравнения: сохранение ничего не делает, закрытие работает без вопроса «сохранить?».

### Task 1: `ui/git_changes.py` — изменения и строки сравнения

**Files:**
- Create: `ui/git_changes.py`
- Test: `<scratchpad>/check_git_changes.py` (не в проекте)

**Interfaces:**
- Produces:
  - `changes(root: Path) -> dict` → `{"repo": bool, "items": [{"path": str, "status": "M"|"A"|"D"|"R"|"U", "orig": str}]}`; `path`/`orig` — POSIX от `root`; `orig` — старый путь (только у `R`, иначе `""`); сортировка по `path`. Не репозиторий или нет git → `{"repo": False, "items": []}`.
  - `diff_rows(root: Path, path: str, orig: str = "") -> dict` → `{"ok": True, "rows": [[left_no, left_text, right_no, right_text, kind], ...]}` или `{"ok": False, "error": str}`; `left_no`/`right_no` — номер строки (1…) или `None` для пустой клетки; `kind` ∈ `"same" | "del" | "add" | "change"`.

- [ ] **Step 1: Скрипт-проверка** — временный репозиторий (`git init`, `user.name/email`), коммит `a.txt` («1\n2\n3\n»), `sub/b.txt`, `del.txt`; потом: правка `a.txt` («1\nдва\n3\n4\n»), новый `новый файл.txt`, удалён `del.txt`. Ассерты:
  - `changes(repo)["items"]` == `[{"path":"a.txt","status":"M","orig":""}, {"path":"del.txt","status":"D","orig":""}, {"path":"новый файл.txt","status":"U","orig":""}]`
  - `changes(repo / "sub")` после правки `sub/b.txt` → один элемент `{"path":"b.txt","status":"M",...}` (только внутри пространства, путь от него)
  - `changes(tmp_without_git)` == `{"repo": False, "items": []}`
  - `diff_rows(repo, "a.txt")["rows"]` == `[[1,"1",1,"1","same"], [2,"2",2,"два","change"], [3,"3",3,"3","same"], [None,"",4,"4","add"]]`
  - `diff_rows(repo, "del.txt")` — все строки `kind == "del"`, правые клетки `None`; `diff_rows(repo, "новый файл.txt")` — все `"add"`
  - файл с байтом `\0` → `{"ok": False, "error": "двоичный файл"}`
- [ ] **Step 2: Запустить** `.venv/bin/python <scratchpad>/check_git_changes.py` — падает на импорте.
- [ ] **Step 3: Реализовать.**
  - Общий `git(root, *args) -> str | None` (None при ненулевом коде / нет git), `cwd=root`, utf-8, `errors="replace"` — как `skills/git_status/run.py`.
  - `changes`: `git rev-parse --show-toplevel`; `git status --porcelain=v1 -z --untracked-files=all -- .`; пути в выводе от корня репо → `(top / p).relative_to(root.resolve())`. У записи `R`/`C` следующий NUL-элемент — старый путь. Статус: `??`→`U`, иначе первая непробельная буква из XY, приведённая к M/A/D/R (`C`→`A`, прочее → `M`).
  - `diff_rows`: левый текст — `git show HEAD:<путь от корня репо>` (для `orig` — по нему; нет HEAD или файла в HEAD → `""`); правый — файл на диске (нет → `""`). `\0` в любой стороне → «двоичный файл». Строки — `splitlines()`. Выравнивание по `difflib.SequenceMatcher(None, a, b, autojunk=False).get_opcodes()`: `equal` → `same`; `delete` → `del` с пустой правой; `insert` → `add` с пустой левой; `replace` → попарно `change`, хвост длинной стороны — `del`/`add`. Больше 5000 строк в сумме → обрезать с последней строкой `[None, "…обрезано", None, "", "same"]`.
- [ ] **Step 4: Запустить** скрипт снова — `OK`, без исключений.
